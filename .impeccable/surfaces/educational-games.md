# Playable educational games

The user rejected decorative backgrounds as a substitute for real Kahoot-like educational games and explicitly asked for working game mechanics and Three.js or an equivalent library. This is a functional extension of Asasera's pinned bilingual game world, not a new identity or a visual-effects exercise.

Experience: answer the teacher's real questions, review the answer, earn resources, then actively play. Three launch choices have distinct rules: Jungle Dash (steer and jump to collect crystals and avoid logs), Sky Builders (time block drops to build a stable tower), and Treasure Quest (navigate an island maze, collect three gems, and open a chest). Native Three.js geometry renders the characters, objects and spatial feedback; the shared game rules decide collisions and scores. The server owns time, resources, decisions and scores for live and self-study games. Public practice runs those deterministic rules locally. Academic answers and marks remain separate from arcade points.

Teacher selects a game at activity launch, students join through the existing PIN, a question/review/game/results loop carries the class, and the projector follows the leading learner's game state and standings. After revealing an answer, the teacher starts the game round and can end it early before advancing. Each round has a three-second countdown and up to 24 seconds of play. Self-study uses the same mechanics with stored round state, resume and single credit for completed points; it is available only with feedback after each answer. A clearly labeled public three-question practice lesson makes the games directly tryable without an account, stores progress in session storage when available, and provides replay. Classic and delayed-feedback homework retain their assessment behavior.

The quality bar is a complete playable loop, clear instructions and objectives, actual input response, server validation, graceful reconnection, durable results, mobile touch and keyboard controls, bounded GPU work, explicit sound opt-in, reduced decorative motion, and a functional board fallback when WebGL is unavailable. Preserve blue #004ccc, four answer identities and the existing world artwork. No concept-seed exercise is needed for this explicitly directed product extension.

Reference mechanisms: Kahoot Treasure Trove and solo game tutorials alternate correct answers with arcade challenges. Asasera uses original names, 3D objects and environments. These are game implementations, not claims of proprietary-code or asset parity.

## Implemented mechanics

| Game | Controls and objective | Resources and scoring |
| --- | --- | --- |
| Jungle Dash / سباق الغابة | Move across three lanes with Left/Right or A/D; jump with Up/W/Space or the touch Jump action. Collect crystals and avoid logs. | A correct answer grants two shields; every learner receives a run. Crystals add 100 points. A collision consumes a shield or subtracts 25 points, floored at zero. |
| Sky Builders / بنّاؤو السماء | Drop a moving block with Space or the Drop button. Movement alternates between the width and depth axes; successful overlap trims the next block. | A correct answer grants four blocks; an incorrect answer grants two. A placed block adds 100 points and a perfect landing adds 150. Each drop consumes one block; empty resources finish the round. |
| Treasure Quest / رحلة الكنز | Move with arrows/WASD or four directional buttons across a 7 × 7 island. Collect at least three gems, then reach the chest; walls block movement and red traps cost energy. | A correct answer grants 24 energy; an incorrect answer grants 16. A valid step uses one energy. Each gem adds 100 points and restores two energy; traps cost two additional energy. Opening the chest adds 300 points and finishes the round. |

Game points, remaining resources and time sit above the canvas. Written event feedback, mode-specific actions and objective instructions remain below it. Live standings and the final podium show arcade points and correct-answer counts separately. Self-study and public practice permit skipping the current game round to continue learning. Live input sequence checks, server time and persistence behavior are documented in [verification](../review/educational-games/verification.md); public practice does not save a teacher report.

## Presentation and implementation bounds

The [root design record](../../DESIGN.md) owns the scoped palette, type, layout and component patterns. The game surface inherits the pinned Montserrat/Neo Sans Arabic pairing, blue brand and four answer identities. Bilingual labels and descriptions are implemented; physical controls and board coordinates remain left-to-right. The game selector reuses jungle, sky and island thumbnails and stage artwork. All new playable 3D objects use native geometry; no new raster images were created.

Three.js loads on demand. Resolution is capped at a 1.5 pixel ratio, with one 1024px directional shadow map; a slow-frame heuristic lowers the pixel ratio to 1 and removes shadows. Rendering pauses when hidden or offscreen, and teardown disposes resources and observers. These source limits are not frame-rate measurements. WebGL errors select the functional simplified board and allow an explicit retry. Device reduced motion initially selects that board and suppresses decorative 3D motion; essential movement remains if 3D is manually selected. The board and 3D view share state and actions. Sound starts off and requires explicit opt-in.

Gameplay controls are at least 56px high and view/sound controls at least 44px high in source. The interactive viewport receives focus on new rounds, with written status, errors and accessible labels accompanying the canvas. Reconnection disables live input while the current in-memory classroom round remains on the server; this does not establish recovery after abrupt server-process loss.

Not canonized: incidental terrain colors, local type outliers, or the simplified treasure board's text-glyph trap marker. The marker is an implementation limitation, not a new icon rule. The initial detector's palette/type/radius notices are advisories; the current source has 4px game-panel/control corners and 12px minimum HUD labels after correction. No second detector run or visual approval is implied.
